- 登录由**用户本人**点的，我没有输入账号密码、没有点登录、没有截屏。**点击的确切时刻我没有记录**（用户只说"点了"）：见下面"时间推断"。

## 方法的修正（云端文档里的前提在本机不成立）
- `run-as … cat /proc/net/tcp*`：**Permission denied（0 行）**。Android 10+ 的 SELinux 不让 app 身份读；shell 身份能读但只返回别的 app 的行（看不到 uid 10251），`ss` 报 netlink Permission denied。
- 所以改用 root：`adb shell su -c cat /proc/net/tcp6`（以及 tcp / udp / udp6），用户已明确同意只读这些表。解析时只保留 uid 列 == 10251 的行、跳过 LISTEN、IP:端口转成点分十进制。**没有抓任何包内容。**
- 因为 `mmcronet::quic` 是 QUIC（走 UDP），我同时读了 udp/udp6。

## 采样
每 ~2.5 s 一拍（tcp、tcp6、udp、udp6 各读一次），60 拍，宿主时钟 08:04:21 ～ 08:06:38。有 6 拍整拍为空（`pid=none` 且 TCP/UDP 都空），其前后两拍都有连接，我判断是 adb 那一拍调用失败，不是连接断开，也不是进程死了（见下）。

## 回答云端的问题
1. **基线（登录页静止）**：08:04:21 ～ 08:05:38 共约 29 拍，uid 10251 **0 条对外连接**（TCP 和 UDP 都是 0）。同一时刻表里其他 uid 的连接（uid 10190 的 ESTABLISHED、系统 uid 0 的 TIME_WAIT/LAST_ACK）与微信无关。
2. **点登录后新增连接**：08:05:40 出现 **1 条新连接：`116.211.235.152:443 ESTABLISHED`**（tcp，IPv4 映射），此后每一拍都在（到 08:06:38 结束），**没有观察到 SYN_SENT**（2.5 s 一拍，握手太快没抓到不奇怪，**不能据此说没有发起过**）。**UDP 全程 0 条。** 没有第二条连接。IP 我没有反查归属，所以**不能说它是腾讯的**；443 是 HTTPS 常用端口，仅此而已。
3. **二选一**：属于"有新连接发起并 ESTABLISHED"那一类，**不是"没有任何新连接"**，所以**不能写"请求没发出去"**。但：
   - 我**不知道这条连接是不是登录请求**（也可能是点击前后微信顺带做的别的联网，比如配置/路由获取）；
   - ESTABLISHED 之后 ~1 分钟里**始终只有这 1 条连接**，没有新增、没有变化；我只看了连接状态，**看不到有没有数据往来、有没有回包**（没读 tx_queue/rx_queue 的变化，也没有抓内容）。
4. **进程**：PID 5632 在采样期间一直是同一个；logcat 里 5632 没有 `Process … has died`、没有 FATAL。

## 时间推断（只是推断）
- 连接首次出现在宿主时钟 08:05:40（上一拍 08:05:38 还没有）。
- 这个窗口里 MultiOpen 最后事件：设备日志 00:06:08～00:06:11（= 宿主时钟 08:06:08～08:06:11，设备与宿主相差约 8 小时 30 秒）出现 `rewriteIntent MobileInputUI → LoginUI`，说明**用户在 08:06:08 之后又回退/重新进入了登录页**（所以那一次页面切换发生在连接建立之后）。
- 因此**我推断**点击登录大约在 08:05:3x，连接是点击后几秒内出现的；**这没有被点击时间戳证实**。
